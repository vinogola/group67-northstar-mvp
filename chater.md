# GROUP 67 TEAM WORKING CHATER: NORTHSTAR SPRINT

---

## 1. TASK BREAKDOWN & BOARD RULES (ANTI-BLACK-BOX)

* **4-Hour Task Limit:** No issue on the project board may exceed 4 hours of estimated work. Any larger deliverable must be decomposed into sub-tasks.
* **Single-Sentence Definition of Done (DoD):** Every board task must feature an unambiguous, testable DoD written in a single sentence.
* **Single Ownership:** Every task must have exactly one primary owner assigned before work begins.
* **Same-Day Status Updates:** Card status movements (To Do → In Progress → In Review → Done) must reflect real-time progress on the day work is completed. Batching status updates at the end of the sprint is strictly forbidden.

---

## 2. COMMIT & EDIT CONVENTIONS (AUDIT TRAIL TRACEABILITY)

* **Structured Format:** All Git commits must follow this exact format: text type: what changed - why it matters.
* **Allowed Types:** feat (new feature), fix (bug fix), docs (go-live note/documentation), test (unit or integration tests), style (formatting/UI fixes), refactor (code restructuring).
* **Traceability Requirement:** Every commit message must reference its corresponding board task ID/number where applicable.

---

## 3. BRANCHING & CODE MANAGEMENT

* **Feature Branches:** Direct commits to the main branch are prohibited. All work must occur on dedicated feature branches named with the task ID and owner initials.
* **Pull Request (PR) Standard:** Every PR requires at least one peer review and sign-off from a teammate before merging into main.

---

## 4. WORK DISTRIBUTION & EQUITY

* **Contribution Balance:** Work will be divided across the pod so every team member has traceable ownership across the build phase.
* **Communication Channels:** Daily updates will be shared in the WhatsApp group throughout the day, followed by an evening check-in to discuss:
  * What was completed today.
  * What will be worked on tomorrow.
  * What needs to be changed.

---

## 5. NON-RESPONSIBILITY & ESCALATION PROTOCOL

If a team member displays zero visible activity (no commits, board updates or communication) for 2 consecutive days:

* **Step 1 Internal Check-In:** The team lead or a peer reaches out directly via chat/phone to check on status and identify blockers.
* **Step 2 Task Re-allocation:** The idle task is unassigned from the member and assigned to another peer to safeguard sprint deliverables.
* **Step 3 Formal Escalation:** If no response or activity occurs by the end of Day 2, the team will log the inactivity in the Day 4 mid-sprint audit snapshot.

---

## 6. PEER RELIABILITY INDEX & CONFIDENTIALITY

* **Confidential Scoring:** Individual Peer Reliability Index evaluations submitted at the end of Day 5 are strictly confidential and will never be shared verbatim with team members.
* **Professional Feedback:** Feedback given during mid-sprint check-ins must remain constructive, evidence-based (derived from the board and audit trail) and focused on delivery success.
